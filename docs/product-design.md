# RiceFinance 产品设计总览

> 版本：V0.3
> 状态：产品方向文档，不承载详细技术设计
> 目标读者：项目作者、AI 编程助手、未来重新进入项目的人

## 1. 这是什么

RiceFinance 是一个面向个人长期使用的财务理解工具。

它不是传统记账软件，也不是投资交易工具。它的核心目标是帮助用户低频、持续地理解自己的财务状态：

- 我现在拥有什么；
- 我的钱如何流动；
- 我的财务状态如何变化；
- 我的消费和资产配置是否符合真实目标；
- 下个月我应该关注什么。

一句话定位：

> 一个用于汇总个人资产、理解消费习惯、追踪净资产变化，并通过 AI Agent 做月度财务复盘的个人工具。

## 2. 项目真实背景

这个项目首先服务作者本人真实使用，其次也是学习项目。

它同时承载几个目的：

- 管理自己的资产、负债、净资产和月度变化；
- 学习 iOS / SwiftUI / SwiftData；
- 学习 TypeScript、前端和未来的 TS 后端；
- 探索 AI Agent 在个人财务复盘里的真实形态。

因此，RiceFinance 不追求一开始就成为商业化大而全产品。它应该优先服务一个真实的人每月会不会打开、会不会复盘、会不会因此更理解自己。

## 3. 不做什么

RiceFinance 暂时不做：

- 每天手工记录每一笔消费；
- 复杂预算系统；
- 银行、微信、支付宝的实时自动同步；
- 股票、基金、加密货币交易；
- 具体投资标的推荐；
- 税务、保险、企业财务等复杂场景；
- 为了“像一个完整 App”而堆功能。

消费流水可以导入和分析，但目的不是做高频记账，而是做低频消费习惯复盘。

AI 可以分析和提问，但不替用户做最终投资决策。

## 4. 核心产品原则

### 4.1 低频体检，而不是高频记账

推荐使用节奏是每月一次：

```text
更新资产
→ 导入或整理消费流水
→ 生成净资产快照
→ 回答 AI 复盘问题
→ 得到月度复盘
→ 留下下月关注点
```

### 4.2 财务镜子，而不是账本

账本回答：

```text
这笔钱花在哪里？
```

RiceFinance 更想回答：

```text
我的财务结构说明了什么？
我的消费习惯说明了什么？
我最近的行为是在靠近目标，还是偏离目标？
```

### 4.3 Agent 复盘，而不是 AI 总结按钮

旧式 AI 功能是：

```text
用户点击按钮
→ AI 生成一段总结
```

RiceFinance 更想要的是：

```text
系统理解当前数据
→ 主动提出复盘问题
→ 用户补充本月上下文
→ AI 生成复盘
→ 系统记住下月关注点
→ 下个月继续追踪
```

### 4.4 个人真实使用优先

如果一个功能看起来完整，但作者本人不会稳定使用，就不是当前优先级。

## 5. 四条主线

RiceFinance 的产品结构可以用四个问题组织。

### 5.1 我有什么

关注资产和负债：

- 现金；
- 存款；
- 固定收益；
- 基金；
- 股票；
- 黄金；
- 外币；
- 信用卡负债；
- 其他负债；
- 净资产。

核心输出：

- 当前总资产；
- 当前总负债；
- 当前净资产；
- 资产类型结构；
- 风险结构；
- 流动性结构；
- 币种结构；
- 账户集中度。

### 5.2 我怎么花

关注消费习惯，而不是逐笔记账。

未来可以支持导入：

- 微信支付账单；
- 支付宝账单；
- 银行卡流水；
- 信用卡账单；
- CSV / Excel / JSON。

核心输出：

- 本月消费主题；
- 必要支出和弹性支出；
- 重复消费和订阅；
- 大额消费；
- 可能的情绪性或惯性消费；
- 真正提升生活质量的消费。

### 5.3 我怎么变

关注时间变化：

- 月度净资产变化；
- 资产结构变化；
- 现金安全垫变化；
- 负债变化；
- 消费主题变化；
- 上月关注点是否改善。

核心机制是月度快照。

### 5.4 我要去哪

关注目标和决策：

- 净资产目标；
- 现金储备目标；
- 年度储蓄目标；
- 投资配置目标；
- 大额支出判断；
- 下月关注点。

这里的重点不是让 AI 替用户决定，而是帮助用户把模糊问题变成可分析的问题。

## 6. 核心闭环

### 6.1 月度资产体检

```text
更新资产和负债
→ 计算总资产、总负债、净资产
→ 查看资产结构
→ 生成净资产快照
```

这个闭环回答：我现在的财务状态是什么样。

### 6.2 AI Agent 月度复盘

```text
读取本月快照和历史变化
→ AI 提出 2-3 个复盘问题
→ 用户补充本月上下文
→ AI 生成月度复盘
→ 保存下月关注点
```

这个闭环回答：这个月发生了什么，下个月我该关注什么。

### 6.3 消费习惯复盘

```text
导入本月消费流水
→ 清洗和归并交易
→ 总结消费主题
→ AI 提出消费反思问题
→ 生成消费习惯复盘
→ 给出下月小实验
```

这个闭环回答：我的钱流向哪里，这说明了什么。

### 6.4 大额决策辅助

用户可以提出自然语言问题：

```text
我现在能不能买一台 15000 元的电脑？
```

系统结合：

- 当前现金储备；
- 总资产和净资产；
- 负债；
- 本月消费；
- 未来已知支出；
- 用户目标和风险偏好；

给出分析性建议，而不是替用户做决定。

## 7. MVP 范围

当前 MVP 应该只围绕最小真实闭环。

### 7.1 必须有

- 资产账户录入；
- 负债账户录入；
- 净资产计算；
- 资产结构统计；
- 月度快照；
- 简单 AI 复盘；
- 复盘结果保存。

### 7.2 下一阶段

- AI 主动提出复盘问题；
- 用户回答本月上下文；
- 下月关注点保存与回看；
- TypeScript 后端迁移探索；
- CSV / JSON 消费流水导入原型。

### 7.3 暂不做

- 微信、支付宝、银行流水实时自动同步；
- 完整消费记账；
- 复杂预算；
- 自动行情；
- 投资交易；
- 多用户协作。

## 8. 技术方向只在这里给结论

详细技术设计不放在本文档，放在 TDC。

## 10. 当前产品宣言

RiceFinance 的核心不是记录每一笔钱花在哪里，而是让用户和自己的财务状态、资产结构、消费习惯持续对话。

它应该帮助用户从：

```text
我大概知道自己有多少钱、花了多少钱
```

走向：

```text
我理解自己的财务结构、风险、目标、变化和消费行为
```
