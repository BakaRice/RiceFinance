# 2026-06-07 18:26:35 CST - Demo V0.1 技术落地方案

### 1. 当前工程状态

当前 RiceFinance iOS 工程仍处于 SwiftUI 默认初始状态，主界面仍是 `Hello, world!`。这说明第一版 Demo 可以从产品主线、信息架构和本地数据模型开始搭建，不需要兼容太多既有实现。

当前工程特点：

- 已有 SwiftUI App 工程；
- 暂无业务模型；
- 暂无页面结构；
- 暂无本地存储；
- 暂无真实数据计算；
- 暂无 AI 分析能力。

### 2. Demo V0.1 产品目标

第一版 Demo 的目标不是做完整财务系统，而是跑通产品最核心的低频体检闭环：

```text
资产录入
↓
净资产计算
↓
结构分析
↓
月度快照
↓
AI / 规则总结
```

V0.1 应优先让用户完成一次完整的月度资产盘点，并在首页看到自己的净资产状态和资产结构。

### 3. V0.1 功能范围

V0.1 必须支持：

- 首页财务总览；
- 资产账户新增、编辑、删除；
- 资产账户列表；
- 总资产、总负债、净资产计算；
- 按资产类型统计；
- 按风险等级统计；
- 按流动性等级统计；
- 手动生成月度快照；
- 查看历史快照；
- 生成简单财务分析报告。

V0.1 暂不支持：

- 银行账户自动同步；
- 股票、基金、黄金实时行情；
- 自动汇率；
- 多设备同步；
- 自建后端；
- 用户登录；
- 复杂预算；
- 每日消费流水记账；
- 具体投资标的推荐。

### 4. 技术选型

第一版建议采用纯本地 iOS 实现：

- UI：SwiftUI；
- 本地存储：SwiftData；
- 图表：Charts，第一阶段可先不用；
- 业务计算：本地 Service；
- AI 分析：先做 Mock / 规则分析，后续替换为真实 AI API；
- 数据同步：V0.1 暂不做；
- 后端：V0.1 暂不做。

选择本地优先的原因：

- 降低第一版复杂度；
- 更适合个人财务数据的隐私要求；
- 可以更快验证产品核心价值；
- 避免后端、登录、同步拖慢 Demo 成型。

### 7. 页面结构

V0.1 建议使用 5 个 Tab：

```text
首页
资产
分析
快照
AI
```

#### 7.1 首页

首页负责让用户在 10 秒内看懂当前财务状态。

展示内容：

- 当前净资产；
- 总资产；
- 总负债；
- 较上月变化；
- 资产结构摘要；
- 风险状态摘要；
- 生成快照入口；
- 生成分析入口。

#### 7.2 资产页

资产页负责回答“我的钱分别在哪里”。

展示内容：

- 资产账户列表；
- 负债账户列表；
- 新增资产入口；
- 编辑资产入口；
- 删除资产能力；
- 按资产类型筛选。

#### 7.3 分析页

分析页负责回答“我的资产结构是否健康”。

展示内容：

- 资产类型占比；
- 风险等级占比；
- 流动性占比；
- 单一账户集中度；
- 简单规则提醒。

#### 7.4 快照页

快照页负责回答“我的财务状态如何变化”。

展示内容：

- 生成本月快照；
- 历史快照列表；
- 快照详情；
- 净资产历史变化。

V0.1 可以先用列表展示历史快照，V0.2 再加入 Charts 趋势图。

#### 7.5 AI 页

AI 页负责生成结构化财务复盘。

V0.1 可以先使用规则分析 / Mock AI 输出：

- 财务状态总结；
- 当前亮点；
- 潜在风险；
- 下月建议；
- 免责声明。

后续接入真实 AI API 时，保持输入输出结构不变。

### 8. 服务层设计

#### 8.1 FinancialSummaryService

负责所有核心财务计算：

- 总资产；
- 总负债；
- 净资产；
- 资产类型占比；
- 风险等级占比；
- 流动性占比；
- 月度变化；
- 月度变化率。

#### 8.2 SnapshotService

负责快照生成：

- 读取当前资产与负债；
- 计算当前汇总结果；
- 创建 `NetWorthSnapshot`；
- 固化 `SnapshotItem`；
- 保存到 SwiftData。

#### 8.3 RuleAnalysisService

负责本地规则分析：

- 现金占比过高提醒；
- 权益占比过低提醒；
- 高风险占比过高提醒；
- 低流动性占比过高提醒；
- 单一账户集中度提醒；
- 外币资产占比提醒。

#### 8.4 AIAnalysisService

V0.1 先作为 Mock 服务：

- 接收结构化财务摘要；
- 输出结构化分析结果；
- 不调用网络。

V0.2 / V0.3 再替换为真实 AI API：

- 构造 Prompt；
- 调用模型；
- 解析 JSON；
- 保存分析报告；
- 展示分析结果。

### 9. 数据流

V0.1 数据流建议如下：

```text
SwiftData Model
↓
Query / Repository
↓
FinancialSummaryService
↓
ViewModel / View State
↓
SwiftUI View
```

生成快照的数据流：

```text
用户点击生成快照
↓
SnapshotService 读取当前资产与负债
↓
FinancialSummaryService 计算汇总数据
↓
创建 NetWorthSnapshot
↓
创建 SnapshotItem
↓
保存 SwiftData
↓
刷新快照页与首页
```

生成分析的数据流：

```text
用户点击生成分析
↓
FinancialSummaryService 生成结构化摘要
↓
RuleAnalysisService / AIAnalysisService 生成分析结果
↓
展示分析报告
```

### 11. V0.1 验收标准

当以下流程可以完整跑通时，V0.1 Demo 即可认为成立：

1. 用户打开 App，进入首页；
2. 用户新增几笔资产账户；
3. 首页自动展示总资产与净资产；
4. 分析页自动展示资产结构；
5. 用户手动生成本月快照；
6. 快照页出现历史记录；
7. 用户生成一份规则分析报告；
8. 报告能给出总结、风险和下月关注事项。
