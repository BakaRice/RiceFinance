# RiceFinance 个人财务 Agent 方向头脑风暴

> 日期：2026-06-20
> 状态：头脑风暴，不是最终 PRD
> 核心问题：如果 AI / Agent 已经存在，个人理财记录软件还应该长什么样？

---

## 1. 当前真实出发点

RiceFinance 首先是一个自己会使用的个人理财工具，其次才是一个学习 iOS、TypeScript、前端与全栈开发的长期项目。

因此，它不应该一开始就被设计成面向大众市场的传统记账软件，也不应该为了“功能完整”而堆页面。更重要的是，它要服务一个真实的个人需求：

- 我想知道自己现在的财务状态是否健康；
- 我想长期追踪自己的净资产变化；
- 我想理解自己的资产配置是否合理；
- 我想在每个月做一次财务复盘；
- 我想理解自己的消费习惯，以及消费背后反映出的生活状态和行为模式；
- 我想让 AI 帮我把模糊的财务感受变成可以讨论的问题。

这个项目的核心不是“做一个软件”，而是建立一个可以长期陪伴自己理解财务状态的工作台。

## 2. 不是传统记账，而是低频财务体检

传统记账软件通常关注：

- 每日消费；
- 流水分类；
- 预算控制；
- 报表统计；
- 消费习惯分析。

RiceFinance 当前更关心：

- 总资产；
- 总负债；
- 净资产；
- 资产类型结构；
- 风险结构；
- 流动性结构；
- 多币种暴露；
- 月度变化；
- 财务目标进度；
- 消费主题和消费习惯；
- AI 复盘与解释。

所以产品的节奏不是“每天记一笔”，而是“每月做一次财务体检”。

推荐使用方式：

```text
每月更新资产数据
→ 生成净资产快照
→ 查看结构变化
→ 导入或粗略整理本月消费流水
→ 回答 AI 的复盘问题
→ 生成月度财务复盘
→ 留下下个月关注点
```

## 3. Agent 模式下的产品理解

如果只是把传统财务软件加上一个“AI 总结”按钮，本质上仍然是旧时代软件。

更理想的方向是：RiceFinance 不只是展示数据，而是帮助用户持续理解自己的财务状态。

它应该像一个个人财务复盘 Agent：

- 记得用户的目标、偏好和历史选择；
- 理解用户当前的资产结构；
- 发现结构异常和变化趋势；
- 主动提出复盘问题；
- 帮助用户推演某个决策的影响；
- 在下个月回看上个月留下的关注点。

传统软件更像：

```text
你录入数据
→ 软件展示图表
```

Agent 型产品更像：

```text
你录入资产、流水和困惑
→ 系统理解状态
→ 系统提出问题
→ 你补充上下文
→ 系统生成复盘和下一步关注点
→ 下个月继续追踪
```

## 4. 产品关系：财务镜子，而不是账本

RiceFinance 可以被理解为一面“财务镜子”。

它不是为了替用户做投资决策，也不是为了替用户追逐收益，而是帮助用户看清：

- 我现在的资产结构是什么样；
- 我的钱主要集中在哪里；
- 我有没有承担自己没有意识到的风险；
- 我的现金是否太多或太少；
- 我的权益资产是否和长期目标匹配；
- 我的负债是否影响安全感；
- 我的钱主要花在什么生活主题上；
- 哪些消费真正提升了生活质量，哪些只是情绪性或惯性支出；
- 我最近的行为是在靠近目标，还是偏离目标；
- 我真正担心的是收益、波动、流动性，还是不确定感。

这意味着，产品应该允许用户表达“模糊的想法”，而不只是填写结构化表单。

例如：

- “我最近想买一台电脑，不知道会不会影响现金流。”
- “我觉得自己现金太多，但又不敢投。”
- “最近市场波动大，我有点想减少权益仓位。”
- “我想知道今年的净资产增长是不是健康。”
- “我感觉最近花钱有点乱，但说不清到底乱在哪里。”
- “我想知道我的消费是不是和我真正重视的事情一致。”

这些自然语言输入可以成为 Agent 分析的重要上下文。

## 5. 核心场景假设

### 5.1 月度财务复盘

每个月，用户打开 RiceFinance，更新资产账户金额，并生成本月快照。

系统随后不只是生成报告，而是先提出 2-3 个复盘问题：

- 这个月有没有一次性收入或大额支出？
- 资产变化主要来自收入、投资波动，还是资产转移？
- 下个月有没有确定的大额支出或资金安排？
- 当前你更关心安全感、增长，还是流动性？

用户回答后，系统生成更贴近真实处境的月度复盘。

### 5.2 投资组合合理性分析

用户希望知道当前投资组合是否合理。

系统不应直接给出“买什么、卖什么”的指令，而应从结构角度分析：

- 现金 / 存款 / 固收 / 权益 / 商品 / 外币占比；
- 高风险资产占比；
- 单一账户或单一资产集中度；
- 流动性是否足够；
- 当前结构是否符合用户自己设定的风险偏好；
- 与上月相比，风险暴露是否明显变化。

输出应是解释性建议，而不是投资建议。

### 5.3 大额支出辅助判断

用户提出一个具体问题：

```text
我现在能不能买一台 15000 元的电脑？
```

系统结合：

- 当前现金储备；
- 总资产和净资产；
- 最近几个月变化；
- 负债水平；
- 下个月是否有已知支出；
- 用户设定的安全垫目标；

给出分析，而不是替用户做决定。

### 5.4 下月关注点追踪

每次月度复盘最后，系统沉淀 1-3 个下月关注点。

例如：

- 继续观察现金占比是否高于目标区间；
- 评估是否需要补足 6 个月应急金；
- 关注权益资产波动对净资产的影响；
- 下月复盘时检查大额支出后的现金安全垫。

下个月生成新快照时，系统主动回看这些关注点。

### 5.5 消费流水导入与消费习惯复盘

除资产和投资组合外，RiceFinance 也可以逐步理解用户的消费习惯。

未来可能支持从不同来源导入消费流水：

- 微信支付账单；
- 支付宝账单；
- 银行卡流水；
- 信用卡账单；
- 手动整理的 CSV / Excel / JSON；
- 其他支付平台或券商、银行导出的明细。

但这个方向的重点不应该是做传统的高频记账，而是做低频的消费行为复盘。

传统记账更关心：

```text
这笔钱属于哪个分类？
```

RiceFinance 更应该关心：

```text
这段时间的钱主要流向了哪些生活主题？
哪些消费是必要支出？
哪些消费提升了生活质量？
哪些消费可能来自压力、无聊、焦虑或惯性？
我的消费方式是否和自己的目标一致？
```

消费习惯分析可以关注：

- 月度必要支出和弹性支出比例；
- 外卖、咖啡、购物、娱乐、订阅等重复消费模式；
- 大额消费是否符合当月计划；
- 情绪性消费或冲动消费的可能线索；
- 长期没有使用价值的订阅和会员；
- 真正带来幸福感、健康、学习或关系质量提升的消费；
- 消费变化与资产变化、现金安全垫之间的关系。

消费复盘的理想流程：

```text
导入本月流水
→ 系统清洗和归并交易
→ AI 汇总消费主题
→ 识别异常、重复和高价值消费
→ 系统提出 2-3 个消费反思问题
→ 用户补充背景
→ 生成消费习惯复盘
→ 给出下月一个小实验
```

“下月小实验”可以很小，例如：

- 暂停 1-2 个低使用率订阅；
- 保留高质量聚餐，但减少无意识外卖；
- 给真正提升幸福感的消费单独留预算；
- 观察压力大时是否更容易产生冲动消费；
- 为学习、健康或关系类消费建立一个正向预算。

这条线的目标不是审判用户花钱，而是帮助用户理解：

```text
钱流向哪里，往往也说明注意力、压力和欲望流向哪里。
```

## 6. 当前阶段最小闭环

第一阶段不追求复杂 Agent，而是先做一个有灵魂的小闭环：

```text
录入资产和负债
→ 生成本月净资产快照
→ 系统提出 3 个复盘问题
→ 用户补充本月上下文
→ AI 生成月度复盘
→ 保存 1-3 个下月关注点
→ 下个月继续追踪
```

这个闭环比一次性做很多页面更重要。

因为只要这个闭环成立，RiceFinance 就不只是资产管理器，而开始成为一个个人财务复盘 Agent。

## 7. 产品边界

RiceFinance 应该做：

- 汇总个人资产和负债；
- 导入并整理来自微信、支付宝、银行、信用卡等来源的消费流水；
- 追踪净资产变化；
- 分析资产结构；
- 分析消费主题和消费行为模式；
- 做月度复盘；
- 结合用户目标进行解释；
- 帮助用户做财务决策前的思考；
- 记录用户的财务偏好和关注点。

RiceFinance 暂时不应该做：

- 高频消费记账；
- 自动银行流水同步；
- 为每一笔消费做复杂手工分类；
- 股票或基金交易；
- 具体投资标的推荐；
- 替用户下结论式地买入或卖出；
- 复杂税务、保险、预算系统。

## 8. 后续需要继续追问的问题

- 我每个月打开这个 App 时，最希望它主动问我什么？
- 我希望它记住我的哪些长期偏好？
- 我愿意输入多少自然语言上下文？
- AI 复盘应该是报告式、对话式，还是两者结合？
- 哪些分析必须可解释，不能只给结论？
- “投资组合是否合理”具体应该拆成哪些判断维度？
- “消费习惯是否健康”具体应该拆成哪些判断维度？
- 微信、支付宝、银行流水导入时，哪些字段是必须保留的？
- 流水数据里哪些信息需要脱敏、加密或本地优先处理？
- 哪些数据必须本地优先，哪些数据可以交给后端和 AI？
- 这个工具对我个人而言，最小但最有价值的版本是什么？

## 9. 暂定产品宣言

RiceFinance 的核心不是记录每一笔钱花在哪里，而是让用户和自己的财务状态、资产结构和消费习惯持续对话。

它应该帮助用户从“我大概知道自己有多少钱、花了多少钱”，走向“我理解自己的财务结构、风险、目标、变化和消费行为”。
